  • pública: escalabilidade "praticamente infinita" C

3 TESTES DE SOFTWARE — o que a banca cobra

incidência ALTÍSSIMA: unidade e integração · ALTA: caixa-preta e regressão · MÉDIA: fumaça, desempenho, dublês

① Níveis (Pressman)

  • unidade = isolada · integração = INTERFACES C (BDMG 25)
  • sistema = ambiente todo (HW, rede, pessoas) · "sistema 1º" E
  • método herdado: retestar em CADA subclasse C

② Integração: stub × driver

  • stub simula o chamado · driver simula o chamador
  • fumaça = abordagem de INTEGRAÇÃO (build diário) C
  • big bang: tudo junto → erro difícil de localizar

③ Caixa-preta: partição e limite

  • partição usa válidas E inválidas · "21, 48, 75" E
  • valor-limite: limite ± precisão nas duas fronteiras (entrada E saída)
  • caixa-preta serve a requisito NÃO funcional C

④ Desempenho × carga × estresse

  • "várias condições de carga" = CARGA C (MPE-CE 25)
  • dar essa definição ao ESFORÇO E (CNPq 24)
  • carga e esforço EXIGEM instrumentação HW+SW C

⑤ Dublês e automação

STUBMOCK
respostas prontasespera chamadas
verifica ESTADOverifica COMPORTAMENTO
  • inverter stub × mock E (TSE 24) · mock no lugar do BD lento C
  • UI mudando muito → teste MANUAL · FIRST: Fast·Independent·Repeatable·Self-validating·Timely

⑥ Regressão · alfa/beta · erro

  • regressão: após QUALQUER mudança · "APENAS classes de erros" C
  • ALFA: usuário no ambiente do DEV · BETA: no local do cliente, sem dev
  • "alfa E beta com dev presente" E
  • erro (humano) → defeito (código) → falha (execução)
  • estático acha DEFEITO · dinâmico vê FALHA
ARMADILHAS: top-down usa STUB, bottom-up usa DRIVER · partição precisa das INVÁLIDAS · fumaça é INTEGRAÇÃO · stub = estado, mock = comportamento

③ REST — as restrições

cliente-servidor · STATELESS · cache · interface uniforme · camadas · code on demand (opcional)

  • usar GET/POST/PUT/DELETE ≠ RESTful E
  • stateless: sem sessão no servidor (BD pode!) · "API deve manter estado" E
  • cache: a resposta se rotula; guarda o cliente/intermediário ("servidor decide" E)
  • REST = estilo, não protocolo · aceita JSON, XML… · HATEOAS = links C

⑥ Web service + PUT/PATCH/POST

  • WS = máquina ↔ máquina · independe de linguagem, HW e SO
  • papéis temporários: o mesmo WS é consumidor e provedor C
  • POST cria (novo a cada chamada) · PUT substitui TUDO · PATCH altera PARTE
  • processamento assíncrono → 202 Accepted
  • endpoint = método + caminho (GET /users/search?name=)
ARMADILHAS: SOAP é XML (nunca HTML) · DELETE é idempotente · verbos HTTP não bastam p/ RESTful · WSDL descreve, UDDI descobre
